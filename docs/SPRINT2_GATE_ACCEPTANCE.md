## Ordinary Write walkthrough

1. On the demonstration branch, inspect the required status name and record the active branch rule, allowed bypass actors and the reviewer's Write role. Use separate author and reviewer accounts and a distinct head for each open demo PR. Keep the PR open through the sequence so each transition remains observable.
2. Open a same-repository PR with an added or modified JavaScript or TypeScript file. Add a harmless file under `demo/policy/` to trigger the HIGH risk rule. Verify that the regular Context run completes its publication and stores the analysis artifact for this head while the gate is waiting. The Write reviewer then approves the head. Verify the success status and review-event receipt, including `reusedAnalysis: true` and `newModelCalls: 0`. After the author pushes another change, check that the original approval cannot authorize it.
3. Obtain a fresh approval. Have a user authorized to dismiss it perform the dismissal and record the actor separately. Have the ordinary Write reviewer request changes on a clean head and capture the resulting restriction. Fault-injection tests supply offline evidence for failures that did not occur in a real run; retain their offline label.
4. For each live transition, record the PR URL, full head SHA, reviewer role, review ID/link, Actions URL, report/comment link, actual status and the Write member's merge-box observation. From the run's artifacts obtain `inspector-receipt-<run_id>-<attempt>/inspector-receipt.json`. Record any missing artifact or denied write directly from the job log.

For an optional resource comparison, run the two modes on the same PR, base, head, workflow revision and configuration. Use the receipt's application duration, new model calls, usage, coverage, omissions and failure reason. Identify cache hits; provider usage can be unknown. Use Actions timestamps to report queue and setup separately. [Actions workflow](../.github/workflows/inspector-live.yml) · [Architecture decision](SPRINT2_GATE_ADR.md)
