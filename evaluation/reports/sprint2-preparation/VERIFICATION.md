# Sprint2 评测准备验证

日期：2026-11-22。基线：`0c1a0b6`，分支：`feat/evaluation-mvp`，加本轮已获用户样例确认的修改。

流程：先 AI 生成结果，然后由我人工复核。本记录只说明离线准备与验证，不是实际模型成绩或人工批准。

## 实际完成

- 20 个逐例中文复核页，包含需求、diff、源码、AI 判断及行为结果；人工决定已记录为已复核，与 AI 输出一致。
- 12 家族、20 快照、113 次行为检查、17 次预期违约（来自 8 个缺陷快照）。20 个 gold 已按单人复核规则升级为 reviewed，仍属 development。
- 当前 138 个来源文件的 SHA-256 与复核包收据一致（原始覆盖 118 个，新增 20 个复核记录）；额外观察的继承键问题单独记录，未改动正式标准答案。
- 新 provider 复用真实 B 检索、C 客户端和 tokenizer；pilot 6 个快照、完整 development 20 个快照的配置生成已准备。
- token 文案修正为模型正文分词加封装余量；耗时分别保存桥接总耗时、检索耗时和 C 处理耗时。
- 修复配置总预留漏算输出余量，以及独立 worker 工作目录中的 tokenizer 资产路径问题；资产仍由 C 校验固定摘要。

## 验证

`npm run test:evaluation` 成功：数据验证、评测 TypeScript 严格检查、重新构建桥接及 **54 项测试，54 通过，0 失败**。见 [完整日志](test-results.tap)。项目整体 `npm run typecheck`、16 个 Jest 测试套件共 482 项测试、构建、Action 语法及生成文件一致性检查均通过。构建保留现有 external-dependency 警告。

新增集成检查覆盖全部 20 个案例 × 两种模式；40 次调用真实 B/C 处理的离线观察均 COMPLETE，8 次跨文件快照检索到 direct-definition。响应是固定的无 finding 模拟输出，因此这些结果仅证明接入，不代表模型表现。

独立 worker 从真实 `.cache` 工作目录执行通过，验证实际分词资产可加载。配置缺费率或支出上限时不能成为 live 计划；缺少凭据时客户端在请求前失败。试验没有发起模型网络请求。
