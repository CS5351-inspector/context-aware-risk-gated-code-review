## 执行顺序与完成条件

| 步骤 | 本轮工作 | 完成条件 |
| --- | --- | --- |
| 1. 样例复核（已完成） | AI 逐例检查需求、源码、反例、修复与正常对照，用户确认 20 例与 AI 输出一致 | 单人确认已登记，原有疑点与局限保留；以后改内容需重新确认 |
| 2. 配置冻结 | 复用已合并的真实 B/C；记录代码及数据指纹、模型、参数、tokenizer、预算、样例和顺序 | 可信账户费率及总预算已填写；构建适配器后生成新计划；不在看过成绩后挑选样例 |
| 3. 小批试跑 | 先运行 6 个快照 × B1/B2 × 1 次，共 12 次评测运行 | 所有开始、失败、超限、未执行记录保留；确认真实相关定义被检索，没有传入 gold |
| 4. 扩展对照 | 首批解决接口问题后，新冻结计划覆盖全部已确认样例，最多 20 × 2 = 40 次运行 | 与首批独立记录；不得挑最佳结果拼接成同一轮；源码/配置变更需重新冻结 |
| 5. 输出评分 | 导出隐藏模式的评分包，人工判断语义、根因、误报、遗漏及不确定项 | AI 建议与最终人工决定分开；未判断的 findings 保持 unresolved |
| 6. 汇总与提交 | 汇总统计、原始记录与 A/D 验收证据，写一页结论 | 检查可复算性和敏感信息；沿用 feat/evaluation-mvp → commit → push 分支 → 新 PR → 组员审核 |

首批预选 DEV-001/002（跨文件契约及修复）、DEV-005/006（diff 可解释缺陷及修复）、DEV-009/010（正常改动）。选择依据是覆盖不同类型，而非观察模型成绩；若人工复核改变此选择，先更新配置和选择理由，再生成计划。这 6 例不是足够估计总体效果的代表性样本。

具体构建、配置与运行命令见 [Sprint2 适配器操作说明](SPRINT2_ADAPTER.md)。需要从对应服务的现有账户确认费率与调用预算，不能用猜测价格、零成本或未知额度触发付费实验。实际凭据仅由本地环境提供，不写进仓库或复核材料。

## 本轮评价什么

- **效果**：C 模块经验证的 findings 中，有多少命中已确认缺陷、多少误报、多少尚不能判断；正常与修复版本是否被误报。区分跨文件契约家族与 diff 内可解释家族，但不预先认定 Context 必要。
- **运行情况**：完成、部分完成、失败、未执行分别统计；开始后的失败仍保留在效果分母中。完整计划与部分计划分别报告。
- **资源**：每次模型调用及重试数、provider usage、缺失 usage、按固定费率估算的费用；费用估算不等同服务账单。实际费用或用量未知时不补零。
- **时间**：worker 总耗时包含进程准备；桥接总耗时、B 检索、C 处理及各请求耗时分别记录。当前组件实验不发布 GitHub 报告，不把其耗时与包含发布的 Action 总耗时直接比较。
- **限制**：合成开发样例、单次试跑、公开行为要求、模型随机性以及可能从 diff 推断答案的线索。增加上下文不保证改善效果、速度或成本。

## 一页结论要回答的问题

1. 实际评测了哪些样例、哪个版本、模型和参数？运行了多少次，哪些未完成？
2. 两种模式发现了哪些真实缺陷，有哪些误报和未决判断？
3. Context 实际取得了什么片段，增加多少调用、token 和时间？是否带来额外发现？
4. 超限和失败是否保留明确原因？两项非功能需求哪些有真实证据，哪些只有离线验证或仍待验收？
5. 如何从原始输出、人工判断和固定配置重新计算结果？哪些限制使本轮不能外推？

在真实试跑及人工评分完成前，不填写模型成绩、不将模拟响应作为真实输出，也不预写“Context 胜出”的结论。
