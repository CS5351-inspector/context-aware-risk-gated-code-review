# F 评测样例人工复核入口

先 AI 生成结果，然后由我人工复核。

本包已逐项阅读全部 20 个案例、20 份标准答案、20 份 diff，以及 12 个家族的全部 base/faulty/fixed/clean 源码与行为检查。AI 建议已写入各案例页；20 个案例已人工复核，与 AI 输出一致；不记录复核人及复核日期。对应案例、标准答案和家族状态已登记为 `reviewed`，用于 development 试跑；不自动升级 formal/heldout 状态。

**复核已完成，后续修改方式**

1. 从下面打开案例，先看需求和改动，再核对实际输入／输出与 AI 判断。
2. 直接修改单例页“AI 对标准答案的判断”，并更新页尾“人工决定、理由”。也可以先在汇总表记下决定。
3. 如果需要改源代码、检查或 gold，记录具体改动；改完重新验证并生成新版本，不能沿用旧 hash 当作已核查证据。

本包记录本轮单人复核完成，内容绑定记录保存在 `evaluation/reviews/`；不声称独立 heldout 金标准已获批准。`validation.json` 是执行证据，不能代替你的判断。

**AI 初步结论与优先看点**

- 现有标准答案与当前执行检查没有发现矛盾：12 个家族、20 个快照，113 次行为检查，17 次预期违约来自 8 个缺陷快照；修复和正常快照符合已列检查。17 个违约不是 17 个独立缺陷。
- 4 个跨文件家族需要审慎描述：依赖源码可以确认错误机制，但旧 diff 已含正确比较、换算、参数顺序或终点表达式，模型可能仅靠 diff 找到问题。“跨文件契约样例”是分类，“必须提供 Context 才能发现”尚未被证明。
- DEV-017/018 的需求明确限制自有键，现有检查遗漏继承键。已执行额外观察：faulty 会读取继承值，base/fixed 不会。建议确认是否将该检查加入下一版；当前未改动正式数据。[额外观察](supplementary-observations.json)
- DEV-015 的负数检查恰好不能区分错误排序；有效失败证据是 `[2,10,1]`。不要把所有边界输入都描述成能检出缺陷。
- 严重性是合成业务假设下的暂定标签。两个 high 有越权／租户隔离语义依据，仍不能据此声称已证明真实项目存在安全漏洞。
- 正常样例只支持约定输入和当前检查范围内的结论；例如未限定超大整数精度、稀疏数组、自定义迭代器，不把这些结果外推为所有 JavaScript 输入的等价性证明。

**证据与复算**

- [最初行为验证输出](validation.json)：审核元数据升级前的逐案例实际观察，模型调用为 0；行为内容未改，当前审核状态以复核记录为准。
- [来源与 SHA-256](source-receipt.json)：当前 138 个文件的 hash（含 20 份复核记录），并保留初始 118 个来源的旧摘要用于核对元数据迁移；文件改变后受影响结论需重查。
- [继承键补充观察](supplementary-observations.json)：单独保存，不冒充已纳入正式数据集的检查。
- 在仓库根目录运行 `node evaluation/validate.cjs` 可重现正式数据验证。输出不会自动写入本包；更新证据时请保留你已填写的人工意见。

这批材料用于开发样例复核，不是独立 heldout 基准、真实 LLM 试跑成绩或门禁验收。后续实验应把样例复核与模型输出评分分开记录。

在仓库根目录核对本包所依据的源文件是否变化：

```sh
python3 - <<'CHECK'
import hashlib, json
from pathlib import Path
receipt = json.loads(Path('evaluation/review-packet/source-receipt.json').read_text())
changed = [name for name, expected in receipt['source_sha256'].items()
           if not Path(name).is_file()
           or hashlib.sha256(Path(name).read_bytes()).hexdigest() != expected]
print('Source files checked:', len(receipt['source_sha256']))
print('Changed or missing:', changed)
raise SystemExit(bool(changed))
CHECK
```

若 `Changed or missing` 非空，应复查对应案例并刷新证据；不要删除人工修改后直接覆盖整个复核包。
